# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные
В данном приложении будут использованы 2 интерфейса.
1. Товар:

````ts
interface IProduct {
    id: string;
    title: string;
    image: string;
    category: string;
    price: number | null;
    description: string;
}
````

`IProduct` - основной товар, в который включены:
`id` - уникальный индетификатор товара;
`title` - заголовок товара;
`image` - изображение товара;
`category` - категория товара:
`price` - цена товара;
`description` - описание товара;

2. Покупатель:

````ts
interface IBuyer {
    payment: TPayment;
    email: string;
    phone: string;
    address: string;
}
````

`IBuyer` - покупатель, в которого включена следующая информация:
`payment` - способ оплаты, который реализован через тип способа оплаты:
`type TPayment = "card | cash"`, где
`card` - оплата картой;
`cash` - оплата при получении.
`email` - электронная почта покупателя;
`phone` - номер телефона получателя;
`address` - адрес покупателя.

### Модели данных

#### Класс `Catalog` (Каталог)

 Класс `Catalog` отвечает за хранение и управление элементами каталога товаров. 

Зона ответственности:

- хранит массив всех товаров;
- хранит товар, выбранный для подробного отображения;

- содержит методы:
  - сохранение массива товаров полученного в параметрах метода;
  - получение массива товаров из модели;
  - получение одного товара по его `id`;
  - сохранение товара для подробного отображения;
  - получение товара для подробного отображения.

Конструктор:
`constructor()` - создает пустую модель каталога товаров.

Поля класса:

- `protected products: IProduct[]` - массив всех товаров.
- `protected preview: IProduct | null` - товар выбранный для подробного отображения. 

Методы:

- `setProducts(products: IProduct[])` - сохранение массива товаров полученного с помощью метода. 
- `getProducts(): IProduct[]` - получение массива товаров из модели. 
- `getProduct(id: string): IProduct | undefined` - получение одного товара по его `id`;
- `setPreview(product: IProduct): void` - сохранение товара для подробного отображения;
- `getPreview(): IProduct | null` - получение товара для подробного отображения;

#### Класс `Basket` (Корзина)
Класс  `Basket` отвечает за хранение товаров, выбранных пользователем для покупки. 

Зона ответственности:
- хранит массив товаров, выбранных покупателем для покупки.
- методы:
  - получение массива товаров, которые находятся в корзине;
  - добавление товара, который был получен в параметре, в массив корзины;
  - удаление товара, полученного в параметре из массива корзины;
  - очистка корзины;
  - получение стоимости всех товаров в корзине;
  - получение количества товаров в корзине;
  - проверка наличия товара в корзине по его id, полученного в параметр метода.

Конструктор:
`constructor()` - создает пустую корзину товаров.

Поле класса:
`protected items: IProduct[]` - массив товаров выбранных покупателем для покупки.

Методы:

- `getItems(): IProduct[]` - получение массива товаров, которые находятся в корзине;
- `addItem(product: IProduct): void` - добавление товара, который был получен в параметре, в массив корзины;
- `removeItem(product: IProduct): void` - удаление товара, полученного в параметре из массива корзины;
- `clear(): void` - очистка корзины;
- `getTotal(): number` - получение стоимости всех товаров в корзине;
- `getCount(): number` - получение количества товаров в корзине;
- `hasItem(id: string): boolean` - проверка наличия товара в корзине по его id, полученного в параметр метода.

#### Класс `Bayer` (Покупатель)
Класс `Bayer` отвечает за хранение, изменение и валидацию данных покупателя. 

Зона ответственности:
- хранит следующие данные:
  - вид оплаты;
  - адреc;
  - телефон;
  - email.
- методы:
  - сохранение данных в модели;
  - получение всех данных покупателя;
  - очистка данных покупателя;
  - валидация данных.

Конструктор:
`constructor()` - создает пустую модель покупателя.

Поля класса:

- `protected payment: TPayment` - вид типа отплаты;
- `protected address: string` - адрес покупателя;
- `protected phone: string` - телефон покупателя;
- `protected email: string` - электронная почта покупателя. 

Методы:

- `setData(data: Partial<IBuyer>): void` - сохранение данных в модели;
- `getData(): IBuyer` - получение всех данных покупателя;
- `clear(): void` - очистка данных покупателя;
- `validate(): Partial<Record<keyof IBuyer, string>>` - валидация данных;

###  Слой коммуникации
### Класс `LarekApi`

Класс `LarekApi` получает данные с сервера и отправляет заказ на сервер. Класс используе композицию в которой в конструктов передается объект `api`, который соответствует интерфейсу `IAPi`. 

Зона ответственности:
- ПОлучение  товаров с сервера;
- Отправка заказа на сервер. 

Конструктор:
`constructor(api: IApi)` - принимает объект для работы с сервером.

Поле класса:
`protected api: IApi` - объект Api через который выполняются запросы. 

Методы:

- `getProducts(): Promise<IProductsResponse>` - выполняет GET-запрос на эндпоинт `/product/` и возвращает объект с массивом товаров;
- `postOrder(order: IOrder): Promise<IOrderResult>` - выполняет POST-запрос на эндпоинт `/order/`, отправляет данные заказа и возвращает результат оформления заказа.

## Документация слоя Представления (View)

### Интерфейсы слоя Представления

#### IHeaderData
Определяет структуру данных для шапки сайта. Применяется в классе `Header`.

```typescript
interface IHeaderData {
  counter: number;
}
```

**Свойства:**
- `counter` — текущее число позиций в корзине.

#### IGalleryData
Описывает содержимое каталога товаров. Используется классом `Gallery`.

```typescript
interface IGalleryData {
  catalog: HTMLElement[];
}
```

**Свойства:**
- `catalog` — коллекция подготовленных DOM-элементов карточек для отображения.

#### IModalData
Определяет структуру данных модального окна. Применяется в классе `Modal`.

```typescript
interface IModalData {
  content: HTMLElement;
}
```

**Свойства:**
- `content` — DOM-элемент, который будет размещён внутри модального окна.

#### ICardData
Базовый интерфейс с общими полями для всех типов карточек товара. Используется абстрактным классом `Card<T>`.

```typescript
interface ICardData {
  title: string;
  price: number | null;
}
```

**Свойства:**
- `title` — наименование товара;
- `price` — стоимость товара. Значение `null` указывает на недоступность товара для покупки.

#### ICatalogCardData
Расширяет базовый интерфейс данными карточки для каталога. Применяется в классе `CatalogCard`.

```typescript
interface ICatalogCardData extends ICardData {
  category: string;
  image: string;
}
```

**Собственные свойства:**
- `category` — наименование категории товара;
- `image` — URL изображения товара.

**Наследуемые свойства из ICardData:**
- `title` — наименование товара;
- `price` — стоимость товара или `null`, если товар нельзя купить.

#### IPreviewCardData
Описывает полную карточку товара для детального просмотра. Используется классом `PreviewCard`.

```typescript
interface IPreviewCardData extends ICatalogCardData {
  description: string;
  buttonText: string;
  buttonDisabled: boolean;
}
```

**Собственные свойства:**
- `description` — текстовое описание товара;
- `buttonText` — текст, отображаемый на кнопке действия;
- `buttonDisabled` — флаг, определяющий доступность кнопки.

**Наследуемые свойства из ICatalogCardData:**
- `title` — наименование товара;
- `price` — стоимость товара или `null`;
- `category` — категория товара;
- `image` — URL изображения товара.

### Классы слоя Представления

#### Класс Header
Отвечает за визуализацию шапки сайта, включая отображение счётчика товаров в корзине.

**Зона ответственности:**
- визуализация количества товаров в корзине;
- обработка клика по иконке корзины;
- генерация события открытия корзины.

**Конструктор:**
```typescript
constructor(
  protected events: IEvents,
  container: HTMLElement
)
```
- принимает брокер событий;
- передаёт контейнер в базовый класс;
- находит элемент `.header__basket-counter`;
- находит кнопку `.header__basket`;
- регистрирует обработчик клика по кнопке корзины.

**Поля класса:**
- `protected counterElement: HTMLElement` — элемент для отображения количества товаров;
- `protected basketButton: HTMLButtonElement` — кнопка открытия корзины;
- `events` — брокер событий (параметр конструктора).

**Сеттеры:**
- `set counter(value: number)` — обновляет числовое значение в элементе `.header__basket-counter`.

#### Класс Gallery
Управляет отображением галереи карточек товаров на главной странице.

**Зона ответственности:**
- приём готовых DOM-элементов карточек;
- отрисовка карточек в галерее;
- замена текущего содержимого галереи.

**Конструктор:**
```typescript
constructor(container: HTMLElement)
```
- принимает DOM-элемент `.gallery` и передаёт его в базовый класс.

**Поля класса:**
- `protected catalogElement: HTMLElement` — контейнер галереи, в который помещаются карточки.

**Сеттеры:**
- `set catalog(items: HTMLElement[])` — очищает галерею и заполняет её переданным массивом DOM-элементов.

#### Класс Modal
Универсальный компонент модального окна.

**Зона ответственности:**
- отображение переданного содержимого;
- открытие и закрытие модального окна;
- очистка содержимого при закрытии;
- обработка клика по кнопке закрытия;
- обработка клика по затемнённой области.

**Конструктор:**
```typescript
constructor(
  protected events: IEvents,
  container: HTMLElement
)
```
- передаёт контейнер в базовый класс;
- находит `.modal__content`;
- находит кнопку `.modal__close`;
- регистрирует обработчик кнопки закрытия;
- регистрирует обработчик клика по оверлею.

**Поля класса:**

### События моделей данных

Модели генерируют события после изменения своего внутреннего состояния:

- `catalog:changed` — обновлён каталог товаров;
- `preview:changed` — изменён товар для детального отображения;
- `basket:changed` — изменилось содержимое корзины;
- `buyer:changed` — изменились данные покупателя.

Данные вместе с этими событиями не передаются. Presenter самостоятельно получает актуальные значения через методы моделей:

```typescript
catalog.getProducts();
catalog.getPreview();

basket.getItems();
basket.getTotal();
basket.getCount();

buyer.getData();
buyer.validate();
```

### Презентер

Презентер отвечает за координацию взаимодействия между Моделями данных и классами Представления.

Поскольку приложение WebLarek состоит из одной страницы, Презентер реализован в основном файле приложения:

**`src/main.ts`**

Отдельный класс для Презентера не создаётся.

**Зона ответственности:**
- создание экземпляров Моделей данных;
- создание экземпляров классов Представления;
- подписка на события приложения;
- получение актуальных данных из Моделей;
- передача данных классам Представления;
- вызов методов Моделей для изменения данных;
- управление последовательностью открытия модальных окон;
- формирование данных заказа;
- вызов методов API.

#### Работа с подробной карточкой
При событии `preview:changed` Presenter получает выбранный товар из модели `ProductCatalog`, определяет состояние кнопки и передаёт готовые значения в `PreviewCard`.

При событии `card:action` Presenter проверяет наличие товара в корзине, добавляет или удаляет его и закрывает модальное окно.

#### Работа с корзиной
При событии `basket:changed` Presenter получает товары, итоговую стоимость и количество товаров через методы модели `Basket`, после чего обновляет корзину и счётчик в шапке.

Событие `basket:open` только открывает модальное окно с уже подготовленной разметкой корзины.

#### Работа с формами
При событии `buyer:changed` Presenter получает данные покупателя и результаты валидации из модели `Buyer`, после чего обновляет обе формы.

Событие `order:open` открывает форму оплаты и адреса, а `order:submit` открывает форму контактных данных.

При событии `contacts:submit` Presenter формирует заказ и отправляет его через `WebLarekApi`.

#### Начальное состояние
Начальное состояние интерфейса задаётся через методы моделей:

```typescript
basket.clear();
buyer.clear();
```

После этого модели генерируют события, по которым Presenter выполняет первоначальное отображение корзины, счётчика и форм.

**Важные принципы:**
- Presenter не хранит данные приложения. Все данные хранятся в Моделях: `ProductCatalog`, `Basket`, `Buyer`.
- Presenter не изменяет DOM напрямую. Для изменения интерфейса используются классы Представления.
- Обновление Представления выполняется:
  - при обработке события Модели данных, сообщающего об изменении данных;
  - при обработке действия открытия модального окна.
- Presenter не должен генерировать новые события внутри обработчиков событий. Он обрабатывает полученные события и вызывает соответствующие методы Моделей и Представлений.
- Обмен информацией между частями приложения выполняется через единый экземпляр брокера событий: `const events = new EventEmitter();`
- Один экземпляр `events` передаётся всем Моделям и компонентам Представления.
